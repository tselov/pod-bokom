# Следующие интеграции

Этап 1 работает без серверной формы, онлайн-брони и оплаты. Секретов в клиентских файлах нет. Данные каталога публичны.

## Т-Банк

Первый рабочий способ после согласования с владельцем: индивидуальная платёжная ссылка, вручную отправленная конкретному клиенту после подтверждения наличия, договора и суммы первого платежа. На сайте общей кнопки оплаты и обещания брони нет.

Для API-интеграции нужен отдельный сервер:

1. Проверить актуальный статус кладовой и подтверждение владельца; создать заказ с уникальным ID, согласованной суммой и версией условий.
2. На сервере создать платёж через интернет-эквайринг Т-Банка. Подписывать запросы и хранить ключи только на сервере, вне GitHub и публичного JavaScript. Публичная страница получает только готовую ссылку на банк.
3. Обработать уведомление банка: проверить подпись, ID заказа, сумму, допустимый переход статуса; повторная доставка не должна повторять операцию. Переход на страницу «спасибо» не подтверждает оплату.
4. Обновить платёжный статус и уведомить владельца только после проверки банковского подтверждения. Условия изменения статуса кладовой и срок резерва определить отдельно; не считать платёж свободным помещением без подтверждения владельца.
5. Подключить фискализацию через «Чеки Т-Бизнеса» с корректными реквизитами, номенклатурой и типом расчёта. Порядок чеков для аванса, полного расчёта и возврата определить для фактической модели аренды.
6. Настроить возвраты и опубликовать согласованные документы. Платёжная ссылка не заменяет договор, реквизиты, политику и информацию об оплате.

Конкретные API-контракты выбирать по актуальной документации банка и подключённому договору эквайринга. Сейчас банковских запросов, токенов и фиктивных платёжных действий в проекте нет.

## Управление каталогом

`id` кладовой постоянный и включает адрес/корпус/номер. В будущем сервер заменит ручное редактирование `units.json`. Операции со статусом должны проверять права владельца и учитывать конфликт одновременных изменений. Данные арендаторов, платежей и договоров хранятся отдельно от публичного каталога.

## Собственная заявка

Безопасный обработчик, опубликованные документы, подтверждённые реквизиты и необходимые согласия предшествуют форме. Только ответ сервера о принятой заявке может вызывать будущую цель `inquiry_success`. Ни открытие Telegram, ни кнопка копирования её не вызывают.
